# Dependency Map

## Intended direction

```text
web routes
  -> shared contracts
  -> IPC client
  -> Controller IPC server
  -> CommandBus
  -> SafetyInterlock
  -> application handlers/services
  -> domain planning and policies
  -> hardware/repository adapters
```

Dependencies must point downward. Domain code must not import Flask, GPIO, serial, Modbus, SQLite, systemd, or browser concepts.

## Current high-coupling areas

| Module | Depends on / owns | Migration observation |
|---|---|---|
| `webapp.py` | config, motion, MQTT, IRIV, PiControl, NUCLEO, persistence and operational state | Primary extraction seam; retain as Controller composition adapter initially |
| `motion.py` | configuration models, pure planning, pulse execution, homing, slots and hardware factory | Split pure calculations/policies before moving execution code |
| `nucleo.py` | serial protocol and exceptions imported from `motion.py` | Move shared errors out first to remove reverse dependency |
| `controller/__main__.py` | builds snapshots, registers every handler, starts IPC | Keep as composition root; reduce implementation logic gradually |
| `web/routes/*` | IPC client and HTTP payload conversion | Good boundary, but error/response schemas are inconsistent |
| `static/app.js` | API, state, navigation, all pages and interactions | Extract store/API/selectors first; do not rewrite page behavior simultaneously |

## Known duplicate paths

The legacy `webapp.py` declares many of the same HTTP endpoints now declared in `web/routes/commands.py`, `config.py`, `slots.py`, `status.py`, and `health.py`. The deployed service uses the separated web app, while Controller still constructs `MotionService` from `webapp.py`. This is duplication, but not proof that either side can be deleted yet.

## Proposed extraction order

1. Shared domain errors and enums.
2. Pure speed, coordinate and motion-plan functions.
3. Typed safety snapshot and reason codes.
4. I/O registry metadata generated by Controller.
5. Demo/slot repository boundaries.
6. Motion, Homing and Drive Power application services.
7. Frontend API client and central store modules.
8. Remove legacy Flask route composition only after route-contract parity tests pass.

## Forbidden dependency checks

Add automated checks that reject:

- `narit_vending/domain` importing Flask, gpiozero, serial, pymodbus or sqlite3.
- `narit_vending/web` importing `motion.py`, hardware backends or gpiozero.
- frontend code containing hardware channel decisions that are absent from API metadata.
- a second hardware-owner process being introduced.
