    KM1 Safety Relay Contact HARDWIRED 60V X/Y cut; 24V Z inspection gate
    Two-State Commissioning Procedure:
    1. Release physical E-Stop button at the cabinet: verify raw DI10 reads 1 (High) and logical E-Stop is CLEAR.
    2. Press physical E-Stop button: verify raw DI10 toggles to 0 (Low) and state transitions immediately to E_STOP.
    3. If the raw bit does not toggle, inspect cabinet wiring and KM1 safety relay contacts. Never compensate in software without two confirmed states.

    Hardware Safety Interlock Gate

    DI10 E-Stop Contact & KM1 Power Relay Diagnostic

    VERIFYING
    DI10 Physical Bit -- High (1) = Released / Closed Loop, Low (0) = Pressed / Open
    Logical E-Stop State -- Must be CLEAR before motion can arm
    Contact Polarity -- NC contact verified via two-state operator test
    KM1 Contactor Relay -- Main 60V power circuit contactor
    On-Site Check Procedure:
    1. Ready state: Release the E-Stop, verify the NC contact is closed, 24 V reaches DI10, raw DI10 reads 1 (High), and Logical E-Stop is CLEAR.
    2. Tripped state: Press the E-Stop and verify the circuit opens, raw DI10 changes to 0 (Low), KM1 removes motor power, and the machine immediately enters ALARM / E_STOP.
    3. Limit test: Manually actuate each axis limit switch and verify that the matching DI0–DI5 card changes to TRIGGERED.

      Advanced reference · command path, configuration and deployment

      Normal motion request

      1. HMI sends CommandEnvelope.
      2. Controller validates safety, Home and limits.
      3. Controller sends versioned USB command.
      4. NUCLEO executes pulses and returns progress.
      5. Controller publishes the resulting snapshot.

      Remote dispense request

      1. MQTT validates request ID, slot and expiry.
      2. Controller rejects duplicate requests.
      3. Safe Z → X/Y → target Z is executed.
      4. Dispense occurs only at a verified slot.
      5. Result is published to the backend.

      Configuration ownership

      machine_config.iriv.json stores axes, travel, Home and Slots. hardware_config.iriv.json stores USB and I/O mapping. Save requires validation and backup; Apply restarts the Controller and clears Homed state.

      Deployment boundary

      Web-only changes restart only Flask. Controller, motion, I/O or protocol changes require full deployment. Deployment never runs Home, Jog, GOTO or Dispense automatically.
