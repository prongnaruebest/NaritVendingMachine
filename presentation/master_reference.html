2. สถาปัตยกรรมฮาร์ดแวร์และกลไก (Hardware & Mechanics)

โครงสร้างกลไกขับเคลื่อน 3 แกนอิสระ (X, Y, Z) ที่ได้รับการสอบเทียบ (Calibration) ล่าสุดเมื่อ 2026-09-07

แกน X (แนวนอนหลัก)
  • ไดรเวอร์: Leadshine HBS860H (Closed-Loop Stepper)
  • กลไก: บอลสกรู MISUMI MTSRL25-1800 (ระยะเกลียว 5 mm/rev)
  • ระยะทางจริงที่วัดได้: 1,600.0 mm (ซอฟต์แวร์จำกัด 1,590.0 mm)
  • อัตราทดและสเต็ป: 68.75 pulse/mm (110,000 pulses ÷ 1,600 mm)
  • Effective Pitch: 23.272727 mm/motor rev (รวมทดรอบ)
  • ความเร็วสูงสุด: 250 mm/s (จำกัดใช้งาน 20 mm/s)
  • อัตราเร่ง/หน่วง: 100 mm/s² (Default)
แกน Y (แนวตั้งยกเสา)
  • ไดรเวอร์: Leadshine HBS860H (Closed-Loop Stepper)
  • กลไก: บอลสกรู MISUMI MTSRL25-1800 (ระยะเกลียว 5 mm/rev)
  • ระยะทางจริงที่วัดได้: 1,600.0 mm (ซอฟต์แวร์จำกัด 1,590.0 mm)
  • อัตราทดและสเต็ป: 68.75 pulse/mm (110,000 pulses ÷ 1,600 mm)
  • Effective Pitch: 23.272727 mm/motor rev
  • ความเร็วสูงสุด: 250 mm/s (จำกัดใช้งาน 15 mm/s)
  • อัตราเร่ง/หน่วง: 100 mm/s² (Default)
แกน Z (แขนผลักหยิบของ)
  • ไดรเวอร์: Leadshine DM542 Microstep Driver
  • กลไก: ชุดสายพานไทม์มิ่ง GTD-A001 (สายพาน 2GT)
  • ระยะชัก (Stroke): 160.0 mm (Safety margin 3.0 mm)
  • สเต็ปปัจจุบัน: 9.0 pulse/mm (Provisional รอตรวจฟัน Pulley)
  • ความเร็วใช้งาน: Default 2.0 mm/s, สูงสุด 10.0 mm/s
  • อัตราเร่ง/หน่วง: 100 mm/s²
  • ระยะยกปลอดภัย (Safe Z): 10.0 mm เหนือแท่นวาง

4. Field I/O & Modbus TCP Register Mapping

IRIV IO เชื่อมต่อผ่านเครือข่าย OT LAN (eth1: 10.0.0.2 ➔ 10.0.0.10:502) มีระบบ Polling ทุกๆ 20ms พร้อมซอฟต์แวร์กรองสัญญาณรบกวน (Debounce Filter)

Digital Inputs (DI0 – DI10)

ช่องชื่อในซอฟต์แวร์สัญญาณอุปกรณ์จริงโหมดความปลอดภัย
DI0x_head_limitสวิตช์ลิมิตหัวแกน X (X Min)Active-High, ปกติเปิด
DI1x_tail_limitสวิตช์ลิมิตท้ายแกน X (X Max)Active-High, ปกติเปิด
DI2y_head_limitสวิตช์ลิมิตหัวแกน Y (Y Min)Active-High, ปกติเปิด
DI3y_tail_limitสวิตช์ลิมิตท้ายแกน Y (Y Max)Active-High, ปกติเปิด
DI4z_head_limitสวิตช์ลิมิตหัวแกน Z (Z Min)Active-High, ปกติเปิด
DI5z_tail_limitสวิตช์ลิมิตท้ายแกน Z (Z Max)Active-High, Debounce 3 samples
DI6z_homeเซนเซอร์ตรวจจับตำแหน่ง Home แกน ZActive-High (แยกจาก Z Min)
DI7product_drop_parkingเซนเซอร์ตรวจแท่นรับสินค้าจุดพักActive-High
DI8product_drop_sensorเซนเซอร์ตรวจการตกของสินค้าActive-High
DI9product_pickup_sensorเซนเซอร์ตรวจช่องรับสินค้าของผู้ใช้Active-High
DI10estopหน้าสัมผัสช่วย Safety Relay / KM1Fail-Safe NC (Normally Closed)

Digital Outputs (DO0 – DO3)

ช่องชื่อในซอฟต์แวร์อุปกรณ์ที่ขับสถานะปลอดภัย (Safe State)
DO0readyไฟสัญญาณสีเขียว (Machine Ready Light)OFF (ดับ)
DO1movingไฟสัญญาณสีเหลือง (Moving Warning Light)OFF (ดับ)
DO2alarmไฟสัญญาณสีแดงและไซเรน (Alarm Buzzer)OFF (ส่งเสียงเมื่อ Fault)
DO3dispenseรีเลย์สั่งกลไกปล่อยสินค้า (Dispense Relay)OFF (Pulse กว้าง 500ms)
ℹ️
SSR Auxiliary Output: เอาต์พุตของ IRIV IO เป็น Solid State Relay สำหรับควบคุมไฟสัญญาณและโซลินอยด์ ห้ามนำมาใช้สร้างพัลส์ความเร็วสูง

5. วงจรความปลอดภัย KM1 และ E-Stop (Safety Interlocks)

ความปลอดภัยของเครื่องจำหน่ายสินค้าถูกออกแบบตามหลักสากลด้วยการแบ่งชั้นการป้องกันเป็น 2 ระดับ:

1. Hardwired Safety Level (ฮาร์ดแวร์ตัดไฟตรง)
ปุ่ม Emergency Stop แบบเห็ดกดล็อกบนแผงควบคุม ต่ออนุกรมเข้ากับ Safety Relay โมดูลตัดไฟฉุกเฉิน ซึ่งสั่งงานคอนแทกเตอร์กำลังหลัก KM1 เมื่อมีการกดปุ่ม E-Stop คอนแทกเตอร์ KM1 จะตัดวงจรไฟกำลัง 60V DC ที่จ่ายเข้าขั้วไฟเลี้ยงของไดรเวอร์ X และ Y (HBS860H) ทันที มอเตอร์จะสูญเสียแรงบิดและหยุดเคลื่อนที่โดยไม่ผ่านระบบประมวลผลใดๆ
2. Software Supervisory Level (ซอฟต์แวร์กำกับ)
หน้าสัมผัสช่วย (Auxiliary Contact) ของ KM1 ต่อเข้า IRIV IO ช่อง DI10 แบบ ปกติปิด (Normally Closed: NC) Controller จะตรวจจับสถานะ DI10 ทุกๆ 20ms หากพบว่าวงจรเปิด หรือเกิดข้อผิดพลาดในการสื่อสาร Modbus Controller จะปรับสถานะเครื่องเป็น E_STOP ทันที พร้อมสั่งตัดพัลส์ของ MCU และบังคับให้ต้องทำการ Home ใหม่หลังปลดล็อก
🚨
จุดอันตรายที่ยังค้างแก้ไข (CRITICAL HARDWARE SAFETY GAP): ตามผังสายล่าสุด คอนแทกเตอร์ KM1 ตัดเฉพาะไฟ 60V ของแกน X และ Y แต่ ไฟ 24V ของไดรเวอร์แกน Z (DM542) ยังคงต่อตรงไม่ได้ผ่าน KM1 ส่งผลให้เมื่อกดปุ่ม E-Stop แกน Z จะหยุดเฉพาะทางซอฟต์แวร์เท่านั้น หาก MCU หรือไดรเวอร์ค้าง แกน Z จะไม่ตัดไฟ ห้ามอนุญาตให้รันตู้จริงจนกว่าช่างไฟฟ้าจะเดินสายไฟ 24V ของแกน Z ผ่าน KM1 ให้เรียบร้อย

6. สถาปัตยกรรมซอฟต์แวร์ Dual-Process & IPC

เพื่อป้องกันไม่ให้ข้อผิดพลาดของ Browser, เครือข่ายเว็บ หรือ JavaScript ส่งผลต่อการควบคุมมอเตอร์ ระบบจึงแบ่งเป็น 2 Process อิสระ:

Browser / HMI (Client) ──[ HTTP:80 ]──> Web Process (Flask) ──[ Unix IPC: ctrl.sock ]──> Controller Process (Master)
                                                                                             ├── SafetyInterlock
                                                                                             ├── CommandBus (Priority Queue)
                                                                                             ├── StateMachine
                                                                                             ├── IRIV IO Backend (Modbus TCP)
                                                                                             └── NucleoLink Backend (USB VCP)

Web Process (narit-vending-web-iriv.service)

  • รัน Flask Web Server บนพอร์ต 80
  • ทำหน้าที่ Render หน้าเว็บ HMI, ไฟล์รูปภาพ, CSS และรับคำขอ REST API
  • ตรวจสอบความถูกต้องของ JSON Schema เบื้องต้น
  • ไม่มีสิทธิ์เข้าถึงฮาร์ดแวร์: ไม่เปิด GPIO, ไม่ต่อ Serial, ไม่ต่อ Modbus
  • สื่อสารกับ Controller ผ่าน Unix Domain Socket /run/narit-vending/ctrl.sock
  • หาก Controller ดับ จะตอบ HTTP 503 ทันที ห้ามแสดงสถานะ READY ปลอม

Controller Process (narit-vending-controller-iriv.service)

  • เป็นผู้ถือกรรมสิทธิ์ความปลอดภัยสูงสุดแต่เพียงผู้เดียว (Sole Motion Authority)
  • รัน CommandBus จัดลำดับคำสั่งแบบ Single-Flight Dispatcher
  • มีคิวพิเศษ (Priority Lane) ให้คำสั่ง STOP และ E-Stop แซงคิวคำสั่งปกติได้ทันที
  • สร้าง MachineSnapshot กลางชุดเดียวส่งต่อให้ Web และ MQTT
  • ดูแลการเชื่อมต่อ Modbus TCP กับ IRIV IO และ USB VCP กับบอร์ด Nucleo

7. เครื่องจักรสถานะระบบ (State Machine Lifecycle)

วงจรการเปลี่ยนสถานะของเครื่องจักรถูกควบคุมอย่างเข้มงวดตามหลักการปลอดภัยสูง:

1. STARTING
สถานะเริ่มต้นขณะเปิดเครื่อง ตรวจสอบ Configuration, โหลดพารามิเตอร์ และเปิดการเชื่อมต่อไปยังบอร์ดต่างๆ
2. E_STOP
สภาวะหยุดฉุกเฉิน มอเตอร์ทุกแกนถูกตัดกำลัง สั่ง Disarm MCU ล้างค่าพิกัด Homed ทันที
3. NOT_READY
ระบบพร้อมเริ่มงานแต่ยังไม่สามารถเคลื่อนที่พิกัดสัมบูรณ์ได้ เนื่องจากยังไม่ได้ทำกระบวนการ Homing
4. HOMING
กำลังเคลื่อนที่ค้นหาจุดอ้างอิงของแต่ละแกนตามลำดับ Z ➔ Y ➔ X ด้วยความเร็วต่ำ
5. READY
ทุกแกนทำ Homing สำเร็จ ระบบพร้อมรับคำสั่งเคลื่อนที่พิกัดสัมบูรณ์ไปยัง Slot ต่างๆ
6. MOVING
มอเตอร์กำลังหมุนตามคำสั่งที่ได้รับอนุมัติ ตรวจสอบลิมิตสวิตช์ตลอดการเคลื่อนที่

8. CommandBus & Long-Move Segmentation

อัลกอริทึมการจัดการคำสั่งและการซอยคำสั่งระยะยาวเพื่อป้องกันมอเตอร์วิ่งค้าง:

  • บัฟเฟอร์ฮาร์ดแวร์จำกัด 10,000 Steps: เฟิร์มแวร์ STM32 รับคำสั่งได้สูงสุดรอบละ 10,000 พัลส์ เพื่อจำกัดความเสียหายหากสายหลุด
  • การซอยคำสั่งอัตโนมัติ: หากต้องการเคลื่อนที่ 1,500 mm (103,125 pulses) Controller จะแบ่งออกเป็น 10 เฟรม เฟรมละ 10,000 pulses และเฟรมสุดท้าย 3,125 pulses
  • ตรวจ Safety ระหว่างเฟรม: ก่อนเริ่มส่งเฟรมถัดไป Controller จะตรวจจับสัญญาณ E-Stop, ลิมิต และเซนเซอร์รบกวน หากมีความผิดปกติจะหยุดส่งต่อทันที
  • Watchdog 500ms: MCU ต้องได้รับพัลส์ HEARTBEAT SAFE จาก Controller ทุกๆ เสี้ยววินาที หากคอมพิวเตอร์ค้างเกิน 0.5 วินาที ไทม์เมอร์จะดับสเต็ปทันที

12. ขั้นตอนการปฏิบัติงานและกู้คืนระบบ (Recovery SOP)

  1. ตรวจสอบความปลอดภัยทางกายภาพ: ตรวจดูแนวรางเคลื่อนที่ X/Y/Z ว่าไม่มีสิ่งกีดขวางหรือสายไฟติดขัด
  2. ตรวจสอบสัญญาณ E-Stop: ตรวจว่าปุ่ม E-Stop ถูกดึงปลดแล้ว และหน้าเว็บ HMI แสดง DI10 เป็น HIGH / CLEAR
  3. ตรวจสอบสถานะการเชื่อมต่อ: ตรวจสอบว่า Controller, IRIV IO และ NUCLEO แสดงสถานะ Online ครบทั้ง 3 รายการ
  4. ลำดับการปลดล็อก: กดปุ่ม Reset Alarms ➔ กด Enable Motion ตามลำดับ
  5. ทำ Home ใหม่ทุกครั้ง: กด Home All และรอจนกระทั่งสถานะเครื่องกลายเป็น READY
  6. เริ่มเคลื่อนที่ด้วยความเร็วต่ำ: ทดสอบ Jog ระยะ 1–5 mm เพื่อดูทิศทางก่อนสั่งงานโหมดอัตโนมัติ

13. การสอบเทียบระยะและระบบส่งกำลัง (Calibration)

สูตรการคำนวณการเคลื่อนที่ที่ใช้ในระบบ:

1. สูตรคำนวณสเต็ปต่อมิลลิเมตร (Lead Screw):
   pulses_per_mm = (motor_steps_per_rev × driver_microsteps) ÷ effective_travel_per_rev
   ตัวอย่าง X/Y: (200 × 8) ÷ 23.272727 = 68.75 pulse/mm

2. สูตรคำนวณระยะเคลื่อนที่ซอฟต์แวร์ปลอดภัย (Software Travel Limit):
   software_travel_limit = measured_physical_stroke − safety_margin_mm
   ตัวอย่าง X/Y: 1,600 mm − 10 mm = 1,590.0 mm

14. คู่มือแก้ไขปัญหาทางเทคนิค (Troubleshooting Guide)

อาการที่พบสาเหตุที่เป็นไปได้แนวทางการแก้ไข
ปุ่ม Jog หรือ GOTO เป็นสีเทากดไม่ได้แกนนั้นยังไม่ได้ Home หรือติดสถานะ E-Stop / Alarmวางเมาส์เหนือปุ่มเพื่ออ่าน Tooltip, สั่ง Home แกนนั้นให้สำเร็จก่อน
Controller Offline บนหน้าเว็บเซอร์วิส Controller ดับ หรือไฟล์ Socket เสียหายใช้คำสั่ง systemctl restart narit-vending-controller-iriv
NUCLEO Offline บนหน้าเว็บสาย USB หลุด, Baudrate ผิด หรือ ST-Link เปลี่ยน IDตรวจสาย USB, กดปุ่ม Reset USB Link บนเว็บ หรือตรวจ /dev/serial/by-id/
IRIV IO Offline (Modbus ขาด)สาย LAN eth1 หลุด, สวิตช์ฮับดับ, IP ผิดตรวจไฟเลี้ยง 24V ของโมดูล IRIV IO และทดสอบ ping 10.0.0.10
มอเตอร์วิ่งผิดทิศทางการตั้งค่า Direction Inversion ในคอนฟิกไม่ตรงกับสายสลับค่า home_direction และ forward_direction ระหว่าง 0 กับ 1 ในไฟล์คอนฟิก
ค่า Noise Counter บนหน้า I/O ขึ้นสูงผิดปกติสัญญาณกวนจากสายมอเตอร์วิ่งขนานกับสายเซนเซอร์ตรวจการต่อสายชิลด์ (Shield Ground), ขันน็อตกราวด์ตู้ ห้ามแก้ด้วยการเพิ่ม Debounce

15. แผนงานและเงื่อนไขความปลอดภัย (Production Gate)

เงื่อนไขบังคับ 8 ประการก่อนเปิดใช้งานโหมดจ่ายสินค้าอัตโนมัติเต็มรูปแบบ:

  1. ✅ ทำการวัดและยืนยันสถานะสองระดับของ DI10 ขณะกดและปล่อย E-Stop เพื่อตั้งค่า polarity_verified=true
  2. ⚠️ แก้ไขวงจรไฟฟ้าให้คอนแทกเตอร์ KM1 ตัดไฟเลี้ยง 24V ของไดรเวอร์แกน Z (DM542) ด้วย
  3. ⏳ ใช้ Oscilloscope ตรวจสอบความถี่และหน้าคลื่นของพัลส์ PA8, PA9, PA5 ก่อนต่อโหลดมอเตอร์
  4. ⏳ จำลองการถอดสาย USB และสาย Modbus เพื่อพิสูจน์ว่ามอเตอร์ตัดการทำงานภายใน 500ms
  5. ⏳ พัฒนาและเปิดใช้งาน Nucleo Motion Backend เต็มรูปแบบใน Controller
  6. ⏳ ทดสอบเคลื่อนที่ทีละแกนที่ความเร็ว 5 mm/s ในระยะสั้น 10 mm พร้อมผู้ควบคุม E-Stop ประจำตู้
  7. ⏳ ทดสอบการชนสวิตช์ลิมิตขณะเคลื่อนที่ เพื่อยืนยันว่าการหยุดทำงานตอบสนองทันท่วงที
  8. ⏳ ทดสอบรัน Demo Slot Sampling 30 ช่อง ครบ 10 รอบโดยไม่มีสัญญาณเตือน Alarm ผิดพลาด
