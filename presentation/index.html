Architecture Deep-Dive · 04

Safety Loop & Power Interlock (KM1)

โครงสร้างความปลอดภัยแบบ Dual-Layer: ฮาร์ดแวร์ตัดกำลังไฟตรง ร่วมกับซอฟต์แวร์ควบคุมสถานะฉุกเฉิน

🔴 Hardwired Safety Layer (ชั้นที่ 1)

ปุ่มกด E-Stop ทางกายภาพบนหน้าตู้ ต่อพ่วงผ่าน Safety Relay ควบคุมคอนแทกเตอร์ KM1 เมื่อกดปุ่ม คอนแทกต์จะเปิดทันที ตัดไฟกำลัง 60V DC ที่จ่ายให้แก่ไดรเวอร์ X และ Y (HBS860H) ทำให้มอเตอร์หยุดหมุนด้วยแรงเฉื่อยทันทีโดยไม่ผ่านคอมพิวเตอร์

🚨
Critical Safety Gap ของ Z: ขณะนี้ไฟ 24V ของไดรเวอร์ Z (DM542) ยังไม่ผ่าน KM1 ทำให้ Z หยุดเฉพาะทางซอฟต์แวร์ — ต้องเดินสายผ่าน KM1 ก่อนใช้งานจริง!

🟢 Software Fail-Safe Guard (ชั้นที่ 2)

1
DI10 NC Feedback: หน้าสัมผัสช่วยของ KM1 ต่อเข้า IRIV IO DI10 แบบ ปกติปิด (Normally Closed)
2
Two-State Verification: ต้องทดสอบกดและปล่อยจริงเพื่อยืนยัน Polarity ก่อนปลดล็อกระบบ
3
Fail-Safe Polling: หากสาย Modbus ขาด หรือค่า DI10 ไม่พร้อม Controller จะเข้า E_STOP ทันที
4
Immediate Disarm: สั่งตัดพัลส์ของ MCU ทันที และส่งข้อความ Disarm ผ่าน USB VCP

Architecture Deep-Dive · 05

CommandBus & Priority Execution

กลไกการรับคำสั่งแบบ Single-Flight Dispatch พร้อมช่องทางด่วนพิเศษสำหรับคำสั่งหยุดฉุกเฉิน

1. Structure of CommandEnvelope

ทุกคำสั่งจาก HMI, REST API หรือ MQTT จะถูกห่อหุ้มเป็น Envelope กลาง:

{
  "command_id": "cmd-8f921a",
  "name": "MOVE_TO_SLOT",
  "source": "hmi_web",
  "created_at": 1725350400.12,
  "arm_token": "arm-550e8400-...",
  "payload": { "slot": 12, "speed": 15.0 }
}

2. Priority Lane vs Normal Queue

P
High-Priority Lane: คำสั่ง STOP, E_STOP, DISARM จะแทรกเข้าประมวลผลทันทีโดยไม่ต้องรอคิว
1

Long-Move Segmentation & Watchdog

สถาปัตยกรรมแบ่งย่อยคำสั่งเคลื่อนที่ระยะไกลตามขีดความสามารถของ Firmware พร้อมการตรวจ Safety ระหว่างทาง

ทำไมต้องแบ่งย่อย (Segmentation)?

เฟิร์มแวร์ Nucleo Candidate v2 ถูกออกแบบตามหลักความปลอดภัย ให้รับคำสั่งพัลส์ได้สูงสุด 10,000 steps ต่อเฟรม เพื่อป้องกันมอเตอร์วิ่งค้างในระยะยาวหากเกิดข้อผิดพลาดในการสื่อสาร เมื่อระบบต้องการเคลื่อนที่ระยะไกล เช่น 44,000 pulses Controller จะคำนวณและแตกเป็นเฟรมย่อยอัตโนมัติ:

Target Move = 44,000 pulses
├── Segment 1: 10,000 steps [Check Safety & Limits]
├── Segment 2: 10,000 steps [Check Safety & Limits]
├── Segment 3: 10,000 steps [Check Safety & Limits]
├── Segment 4: 10,000 steps [Check Safety & Limits]
└── Segment 5:  4,000 steps [Final Position Verify]

Watchdog & Heartbeat Architecture

1
500ms Hardware Watchdog: เฟิร์มแวร์ STM32 มีตัวนับเวลาถอยหลัง หากไม่ได้รับคำสั่ง HEARTBEAT SAFE ภายใน 500ms ไทเมอร์ขับสเต็ปจะหยุดทันที
2
Fresh Sensor Verification: Controller จะส่ง Heartbeat ได้ก็ต่อเมื่ออ่านค่าจาก IRIV IO Modbus สำเร็จและสถานะปลอดภัย
3
Inter-Segment Position Sync: หลังจบแต่ละ Segment ระบบจะอัปเดตพิกัดปัจจุบันใน MachineSnapshot ทันที
⚠️
No Software Interpolation by UI: หน้าเว็บ Browser มีหน้าที่เพียงส่งเป้าหมายสุดท้าย การแบ่งพัลส์เป็นหน้าที่ของ Controller เท่านั้น
Stop Anywhere
สามารถกดปุ่มหยุดได้ทันทีทุกขณะ โดย Controller จะยกเลิก Segment ถัดไปทันที
Limit Enforcement
หาก Limit Switch ถูกชนระหว่าง Segment มอเตอร์จะหยุดทันทีภายในระดับ Millisecond
Smooth Re-sync
ถ้าการเคลื่อนที่หยุดกลางทาง ระบบจะบันทึกพิกัดจริงล่าสุด และบังคับให้ผู้ใช้ตรวจเช็ค

Troubleshooting

อาการแนวทางตรวจสอบ
ปุ่มแกนถูก disableวาง pointer อ่านเหตุผล · ตรวจ Home ของแกน, E-Stop, Stop latch, alarm และ connection
ปรับ speed แล้ว GOTO Execute ไม่ได้ทำ Validate → Preview → Arm ใหม่ เพราะ arm token ถูกยกเลิก
ปรับ speed แล้ว Min/Max ไม่ได้ตรวจว่าแกนนั้น Home แล้ว · speed ปกติไม่ควรล็อก direct motion
Controller Offlineตรวจ web/controller services และ IPC socket · อย่าสรุปว่า NUCLEO หรือ IRIV offline ตามไปด้วย
NUCLEO Offlineตรวจ USB path, baud rate (115200), firmware/protocol handshake · ลอง Reset USB Link
IRIV Offlineตรวจไฟเลี้ยง, LAN, host/port (10.0.0.10:502), Unit ID 255, Modbus polling
Motor หยุดกลางทางตรวจ E-Stop, Stop latch, limit, driver alarm, USB heartbeat, Event Log
Noise counter สูงตรวจสาย, shield, ground, ระยะสาย, แหล่งรบกวน · ห้ามเพิ่ม debounce อย่างเดียว
Home ไม่สำเร็จตรวจ sensor DI0–DI6 ว่าทำงาน · ตรวจว่า E-Stop clear · ตรวจ time watchdog ของ home
DI10 ไม่เปลี่ยนสถานะตรวจสาย E-stop/relay · ห้ามแก้ software ชดเชย ต้องแก้ hardware
